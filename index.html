Projetos em prática

Três contextos para exercitar o mesmo cuidado: entender o problema, representar as regras e conferir o resultado.

Backend · Domínio financeiro

FinTrack API

API REST para registrar operações e consolidar carteiras com renda fixa, ações, fundos imobiliários e criptomoedas. O desafio é reunir ativos com regras de rentabilidade diferentes em um domínio comum.

  • Cálculos financeiros com Decimal e estratégias por indexador.
  • Autenticação JWT, persistência relacional e migrações versionadas.
  • Testes de domínio e integração, com validação no GitHub Actions.
  • Python
  • FastAPI
  • PostgreSQL
  • SQLAlchemy
  • pytest
  • Docker

Uma decisão e um aprendizado

As regras de cálculo ficam separadas do FastAPI e do SQLAlchemy. Um dos aprendizados foi corrigir a ordenação de compras e vendas na mesma data, acompanhando a correção com testes de regressão para saldo e preço médio.

A interface demonstrativa foi prototipada com geração por prompt em uma ferramenta da Vercel. Meu foco técnico nesse projeto está no backend, no domínio e na persistência.

Backend · Estatística · Visualização

API Performance Monitor

API para armazenar medições de latência, consultar estatísticas e gerar gráficos em PNG. Conecta operações HTTP à análise da distribuição dos tempos de resposta.

  • Datasets e medições com validação, paginação e persistência em PostgreSQL.
  • Média, mediana, dispersão, percentis, limites e possíveis outliers.
  • Histograma, boxplot, curva acumulada, frequência e gráfico por ordem da medição.
  • FastAPI
  • NumPy
  • Matplotlib
  • PostgreSQL
  • Alembic

Como os dados viram uma análise

O domínio valida as medições e calcula estatísticas sem depender do framework HTTP. Os gráficos são gerados em memória e entregues diretamente em PNG. O exemplo desta página usa [100, 100, 110, 120, 130, 450] ms.

Em desenvolvimento. A versão atual recebe dados enviados pelo usuário; a coleta automática de APIs externas está planejada.

SQL · Análise de dados · Negócio

Nexus Cloud

Laboratório com dados fictícios de uma empresa de serviços de nuvem. As análises partem de pedidos das áreas comercial, financeira e de infraestrutura para construir consultas PostgreSQL.

  • Relacionamentos entre clientes, serviços, contratos e cobranças.
  • Agregações, rankings e interpretação das regras de cada indicador.
  • Roteiro de 30 desafios, com gráficos e dashboard como etapas de evolução.
  • SQL
  • PostgreSQL
  • Docker Compose
  • Jupyter
  • Streamlit

O que estou exercitando

Antes de escrever a consulta, definir a população, a granularidade e o significado do indicador. Distinguir o valor contratado, a cobrança gerada e a receita recebida muda a interpretação de um relatório.

O ambiente já inclui Jupyter e Streamlit. As análises visuais e o dashboard fazem parte do roteiro de desenvolvimento, sem representar uma entrega concluída.

Também exploro matemática, algoritmos e programação em exercícios independentes.

Como venho aprendendo

Estou me desenvolvendo em Backend Python e Análise de Dados. Aprendo investigando problemas: como representar uma regra de negócio, manter dados consistentes e explicar o que um resultado significa.

Nos projetos, tenho praticado a separação entre domínio, API e persistência, os testes de regras de negócio e a análise com SQL e estatística. A matemática aparece como ferramenta para entender e conferir os cálculos.

Busco uma oportunidade de estágio para contribuir, aprender com uma equipe e aprofundar essa base em problemas do dia a dia.
